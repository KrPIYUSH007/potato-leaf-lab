# V5 feature-fusion SVM experiment

## Measured result — 26 November 2026

V5 selected **ConvNeXt-Tiny features + StandardScaler + L2 normalization + RBF SVM**, with C=2, gamma=scale and ordinary class weighting. It achieved **82.12% validation accuracy** and **80.04% macro-F1**, with **372/453 correct predictions**. The selected deployment bundle contains the ConvNeXt extractor and the fitted SVM pipeline.

The experiment evaluated 31 scored candidates across single SVMs, calibrated voting and specialist cascades. Four feature extractors were examined during the search. The selected single-backbone candidate had the highest validation macro-F1. This result supports comparing feature fusion empirically for this dataset.

|---|---:|---:|---:|
| v1, locally trained | 68.87% | 63.36% | 312 |
| v4, teammate-submitted predictions | 80.35% | 78.03% | 364 |

Relative to v4's submitted predictions, v5 adds 8 correct predictions, **1.77 percentage points in accuracy** and **2.01 percentage points in macro-F1** on the shared validation partition. These scores follow validation-based model selection. Final test performance remains unmeasured.

## Design

V5 adds EfficientNet-B0 to the previous InceptionV3, ResNet-50 and ConvNeXt-Tiny feature extractors. All four networks use frozen ImageNet weights. Each image is evaluated in its original and horizontally mirrored orientation, and the two feature vectors are averaged.

The experiment compares three representations.

| Representation | Features |
|---|---|
| ConvNeXt | ConvNeXt-Tiny alone, 768 dimensions |
| Tri | InceptionV3 + ResNet-50 + ConvNeXt-Tiny, 4,864 dimensions |
| Quad | Tri plus EfficientNet-B0, 6,144 dimensions |

Each backbone's vector is L2-normalized before concatenation. An SVM pipeline then applies training-fitted standardization, row-wise L2 normalization and RBF classification.

The fixed search uses C values 0.5, 2 and 8, each with ordinary or balanced class weighting. The best candidate per representation is calibrated using three stratified, group-disjoint folds within the training partition. The scaler is inside the calibrated pipeline, so each fold fits its own preprocessing on its training subset.

Four declared voting mixtures combine the calibrated models. Two calibrated binary experts handle fungi/pest and phytophthora/fungi ambiguity, using nine combinations of thresholds 0, 0.1 and 0.2. The experiment chooses among single models, voting and specialist cascades by validation macro-F1, then validation accuracy. Exact ties keep the earlier candidate. The search plan is recorded before extraction in `runs/v5-cache/plan.json` and copied into the final run metadata.

The 2,112 training and 453 validation images use the unchanged dataset manifest. The 450 test images remain reserved. All reported selection scores are validation scores after model selection.

## Commands

Use the existing training environment described in [BASELINE.md](BASELINE.md).

```powershell
& ./.venv/Scripts/python.exe -m leaflab.v5 --device cuda
& ./.venv/Scripts/python.exe -m leaflab predict --model runs/baseline-v5 --image 'path/to/leaf.jpg' --device cuda
```

Default extraction batch size is 8 images, or 16 views after mirroring. Use `--batch-size` and `--workers` to adjust memory and loading. Use new `--out` and `--report` paths for a new experiment. Existing published bundles are protected from overwrite.

## Reproduction and saved artifacts

Source image hashes and the frozen manifest are checked before cache reuse. Cache identities include the ordered paths, image hashes, manifest hash, weight presets, transform descriptions, package versions and mirroring policy. Model weights, feature caches and staging files remain in the existing local `runs/` directory.

The saved bundle contains the selected classifier and every required feature extractor state, with artifact hashes in `metadata.json`. The prediction command reconstructs feature extraction from those saved states, checks hashes, performs the same two-view preprocessing and applies the selected classifier. It does not need a teammate's feature arrays to classify a new image.

| Location | Purpose |
|---|---|
| `runs/baseline-v5/` | Local image-prediction model bundle |
| `runs/v5-cache/` | Versioned feature arrays and extraction states |
| `reports/baseline-v5/metrics.json` | Selected model's validation metrics |
| `reports/baseline-v5/candidates.json` | SVM, vote and cascade selection scores |
| `reports/baseline-v5/validation_predictions.csv` | Per-image validation predictions |
| `reports/baseline-v5/confusion_matrix.csv` | Category-level validation confusion matrix |
| `reports/baseline-v5/run.json` | Search plan, environment, manifest and model hashes |

The new search uses the same validation partition that informed earlier versions. It can provide a useful engineering comparison, but final assessment remains pending on the reserved test partition. Model size and CPU latency also remain to be measured for deployment selection.
